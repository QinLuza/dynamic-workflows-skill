# dynamic-workflows：把词元当鸡蛋

> 给"多子代理工作流"写脚本的**作者契约 + 判断层**——出自 ZCode harness 的 bundled skills，
> 含 2026-10-24 的「词元经济学」修订。MIT 开源。

## 这是什么

当你的 agent 宿主能跑"用一段 TypeScript 脚本编排一群模型子代理"的动态工作流时，
这份技能教会——更准确地说，**约束**——主模型把脚本写对：

- **拓扑怎么选**：每项工作一个新子代理，还是共享一个做校准判断；流水线默认、汇合只在需要全部结果的地方；
- **结果怎么定类型**：接口加 JSDoc 注释，弱模型的产出变成强模型可以直接分支消费的值；
- **门禁怎么设**：构建过没过、测试绿没绿，用命令退出码判定，不用"问一个代理它说过了"；
- **报告怎么交付**：边发现边 `report()`（run 挂了也保住已完成的发现），`return` 回四字段报告；
- **上下文怎么花**：这是 2026-10-24 修订的主角，见下文。

它不是提示词合集，而是两层：

| 层 | 内容 | 谁来执行 |
|---|---|---|
| 契约层（§16） | 类型化结果、phase 标记、channel 必须关、`world.run` 命令名字面量…… | 编译器，违反直接报错 |
| 判断层（§1–15） | 几个代理才够、谁共享上下文、什么要新眼睛复核、什么时候留洞让发现写剩下的拓扑 | 写脚本的模型 |

## 设计出发点

这份技能的每条规则都从同一本账里长出来。四个出发点：

### 1. 让鸡蛋更耐用

词元就是鸡蛋：**易碎、有数、且每一轮都要重新付一遍**。

主对话的成本不是"写了多少"，而是"每一轮都把全部上下文重新读一遍"——
内容 × 轮数才是真单价。一个真实工作日的账单（2026-10-24，单机单用户）：
全天 504.9 万 token，其中主模型（强模型）467.9 万，占 **92.6%**；
跑全部测试、评测、六步验证、16 篇入库的工作流子代理（弱模型）只花 37 万。

大头不是活重，是**上下文反复重读**。技能的第一目标：每个鸡蛋都花在刀刃上，
而刀刃是判断，不是转录。

### 2. 让强模型做自己擅长的事

判断、规划、写码、权衡取舍、对不一致的证据做裁决——这些留在主对话，
也只把这些留在主对话。"从 17KB 测试日志里找出失败行""把一段 JSON 抄成摘要"
这类机械活，从强模型手里拿走，是这份技能存在的理由之一。

### 3. 让弱模型更配合强模型工作

弱模型可靠不是靠许愿，是靠结构。技能给了三种结构：

- **确定性门禁**（`world.run`）：测试过没过看退出码，零幻觉空间——
  反模式表里明写："让子代理跑测试然后报告结果"是在为 `world.run` 三行代码能判定的事付一个会话；
- **类型化结果**（`ask<T>` + JSDoc）：弱模型按 schema 回值，强模型的脚本直接分支，
  不需要再读一遍原文；
- **诚实的 persona**：写给子代理的角色必须包含"过不去就升级说明，不许绕过或造假"——
  造假是"不可能通过的关卡"下最顺从的解，把不可能说在前面，诚实才是便宜的那个选项。

### 4. 主对话保持干净，让上下文更耐用

长输出留在工作流的 run 日志里，回到主对话的只有摘要和路径。

这不是洁癖，是复利：主上下文越干净 → 压缩来得越晚 → 指令跟随越稳 →
一个会话能干完的活越多。反过来，把 17KB 的 verify 输出读进主对话，
它会在此后的**每一轮**被重新计费，直到压缩把它抹掉——连同可能还有用的细节一起。

## 词元经济学：四条硬规则（2026-10-24 修订）

上面那笔 37 万的弱模型账单，复盘后发现自己也花得不精：三个"记录员"子代理
吃掉了大头——它们领到的活是从格式固定的 JSON 输出里抄数字，而且默认跑在
弱模型的最高推理档。修订把教训固化成四条规则，已写进技能正文：

1. **能 parse 的别让模型读**（§5 Parse what code can parse）：固定形状的输出
   （JSON、总结行、格式保证的判定行）由脚本 `JSON.parse` / 正则提取，零模型 token；
   模型会话只留给需要"读懂"的自由文本，且只喂最小切片或文件路径。
2. **推理档位匹配**（§2）：为杂活点名的轻量模型默认跑最高推理档，会用长篇推理
   重新推导一个正则就知道的答案——提取、填表类代理显式写 `$low`，默认档留给判断。
3. **return 是摘要，不是转写**（§10）：把几 KB 的 stdout 尾巴回传给主对话，
   等于把工作流本该吸收的污染，按主模型费率重新引进来，并在之后每一轮继续计费。
   回解析后的数字、判定、决策所系的那几行；其余给文件路径。
4. **合并 run**（§12 反模式表）：一个命令起一个工作流，是在为一次脚本编译、
   一份脚本维护、一轮确认窗口反复付固定开销；同类杂活并进一个 run。

以及一条反向判断：**主对话必须逐字消费输出的活，不值得套工作流**——
"跑完 → 摘要回来 → 主对话还得看原文"比直接在主对话跑一遍更贵。
工作流的真收益从来不是总 token 下降，而是污染不进主上下文 + 并行 + 确定性门禁。

## 技能速览（16 节地图）

| 节 | 一句话 |
|---|---|
| §1 何时用、用多大 | 只有用户点名工作流才启动；点名即绑定，剩下只决定脚本多小 |
| §2 子代理拓扑 | 每项一个新代理 vs 共享一个校准代理；名字是身份也是缓存键；推理档位匹配 |
| §3 新眼睛 | 草作者看不见自己的空洞，评审必须是没见过草稿的新上下文；问"什么会弄坏它"而不是"这好吗" |
| §4 类型化结果 | JSDoc 是最便宜的质量杠杆；传路径不传内容 |
| §5 世界读入 | `world.run` 是确定性门禁；先选门禁再写门禁；能 parse 的别让模型读 |
| §6 先测再交 | 固定逻辑先过 EvalWorkflowSnippet，别拿整跑当试错 |
| §7 默认流水线 | `Promise.all` 是汇合，汇合是栅栏；能逐项交接就逐项链 |
| §8 phase 分组 | 用户看到的是 phase 图，不是三十张步骤卡 |
| §9 为用户写 | phase 名、子代理名、报告——写给用户，不写给机器 |
| §10 验证与交付 | 发现要有独立确认，确认不了就标 `unconfirmed` 留着；return 是摘要不是转写 |
| §11 完整示例 | 逐文件评审 + 分诊 + 逐发现确认的流水线全本 |
| §12 反模式表 | 每一行都是真金白银换来的：fan-out 被提出去变队列、未关 channel、KB 级回传…… |
| §13 提交之后 | 诊断改草稿文件走 `path`，绝不整段重贴；错 run 用 amend 吃缓存，别推倒重来 |
| §14 子代理升级 | 关卡过不去、指令自相矛盾——升级问人，不许磨 round 或造假 |
| §15 洞（hole） | 形状未知的地方留洞，让发现写剩下的拓扑；答案缺失用 ask，不用洞 |
| §16 工具契约 | 编译器对着检查的那份 facade：类型、phase、channel、artifact、world.run 字面量 |

## 实战样例：一个工作日的拆账

以 2026-10-24 的真实任务为样例（RAG 评测语料扩容）：

- **强模型（主对话）**：核对半成品 diff、写 12 条跨篇多跳用例、修环境问题决策、
  改三份设计文档、写全部工作流脚本——判断密集，留在主对话；
- **弱模型（工作流子代理）**：5 个后台 run 承包了全量测试、标注、全库重建、
  门禁跑分、六步 verify、16 篇文档入库与台账核对——全走确定性命令门禁，
  子代理只做三件事：提取失败清单、汇总跑分、交叉核对入库台账；
- **结果**：21 篇语料 / 341 chunk / 74 条用例 / verify 六步全绿；
  三次环境坑（Windows 下 `npm` 不能直接 spawn、`bash` 撞上 WSL 壳、CLI 参数勘误）
  全部在工作流侧修掉，17KB 的 verify 输出始终没进主对话。

这笔账同时暴露了修订的动机：37 万弱模型 token 里，记录员们本可以接近零。

## 安装与适配

```
~/.agents/skills/dynamic-workflows/
├── SKILL.md      # 本文介绍的本体（契约 + 判断层）
├── patterns.md   # 拓扑目录：流水线、评审扫荡、judge 面板、洞的形态……
└── examples.md   # 完整可读的成套脚本
```

- 放进技能目录即用；正文里的 `${ZCODE_SKILL_DIR}` 占位符指本技能所在目录。
- **宿主要求**：一个 CreateWorkflow 类工具（脚本化编排模型子代理）。
  §16 是这类工具的契约参考（`agent()/ask`、`world.run`、`phase`、`hole`、
  `channel/future`、`artifact/report`）。
- **其它编排器**：判断层（§1–15）不依赖任何具体工具；契约层的概念
  （子代理会话、命令门禁、阶段标记、留给人填的洞、阶段间通道、用户面产物）
  在多数编排框架里都有对应物，对照移植即可。
